โปรแกรมนี้พัฒนาด้วยภาษา Python ร่วมกับไลบรารี Kivy โดยทำงานในรูปแบบของแอปพลิเคชัน GUI ที่มีระบบสลับหน้าจอ (ScreenManager) ตัวแอปถูกออกแบบให้เป็น "เกมอาร์เคดแนวเอาชีวิตรอด" ซึ่งผสมผสานระหว่างการรับค่าจากคีย์บอร์ด (Typing) เข้ากับระบบฟิสิกส์พื้นฐานเพื่อสร้างความท้าทายให้กับผู้เล่น


โครงสร้างหลักของโค้ด (Core Code Structure)
โค้ดถูกแบ่งการทำงานออกเป็นคลาส (Class) ต่างๆ อย่างชัดเจน โดยมี ScreenManager เป็นตัวควบคุมการเปลี่ยนหน้าต่างทั้งหมด 4 หน้าหลัก ได้แก่:
1. MainMenuScreen: หน้าต่างเมนูต้อนรับ ทำหน้าที่เชื่อมโยงไปยังหน้าตั้งค่าหรือหน้าเริ่มเกม และเป็นจุดเริ่มต้นในการสั่งเล่นเพลงพื้นหลัง
2. SettingsScreen: หน้าตั้งค่าตัวแปรเวลา (15, 30, 60 วินาที) โดยเก็บค่าไว้ในตัวแปรออบเจกต์ เพื่อให้หน้าเกมเพลย์ดึงไปใช้งานต่อ
3. GameScreen: หน้าจอหลักที่เป็นหัวใจของระบบเกม จัดการเรื่องฟิสิกส์ การคำนวณคะแนน การเกิดของวัตถุ และการดักจับปุ่มกด
4. ResultScreen: หน้าต่างสรุปผล นำข้อมูลจากหน้าเกม (เวลาที่ใช้, คะแนน) มาคำนวณเป็นค่า WPM (คำต่อนาที) และแสดงผลแพ้/ชนะ


หลักการทำงานของระบบเกมเพลย์ (Game Mechanics)
1. ระบบ Game Loop (60 FPS)
ในคลาส GameScreen เมื่อผู้เล่นเข้าสู่หน้าจอ โปรแกรมจะใช้คำสั่ง Clock.schedule_interval(self.update, 1.0 / 60.0) เพื่อสร้างลูปการทำงาน 60 รอบต่อวินาที ลูปนี้จะทำหน้าที่:
- นับเวลาถอยหลัง
- เลื่อนตำแหน่งแกน Y ของก้อนเมฆคำศัพท์ให้ลดลง(จำลองการตกลงมาตามแรงโน้มถ่วง)
- ตรวจสอบการชนกันระหว่างออบเจกต์ (Collision Detection) เช่น เช็คว่าก้อนเมฆหรือยานอวกาศตกลงไปแตะพิกัดความสูงของลาวาหรือไม่

2. ระบบการรับค่าและการโจมตี (Input & Combat System)
- ใช้ Window.bind(on_key_down=...) เพื่อดักจับการพิมพ์ของผู้เล่นในระดับ OS ทำให้สามารถรับค่าได้แม้จะไม่ได้คลิกที่กล่องข้อความ
- เมื่อผู้เล่นพิมพ์ข้อความ โปรแกรมจะเก็บอักขระไว้ในตัวแปร typed_word และแสดงผลบนหน้าจอ
- เมื่อกดปุ่ม Spacebar หรือ Enter โปรแกรมจะนำข้อความที่พิมพ์ไปวนลูปเทียบกับคำศัพท์ทั้งหมดที่ลอยอยู่บนหน้าจอ หากตรงกัน จะทำการทำลายก้อนเมฆนั้นทิ้ง บวกคะแนน และเคลียร์ข้อความที่พิมพ์ไว้

3. ระบบพลังชีวิตอิงตามพิกัด (Visual Health System)
- เกมนี้ไม่มีตัวแปรหลอดเลือด (Health Points) แต่ใช้พิกัดแกน Y ของคลาส PlayerShip เป็นตัวแทนพลังชีวิต
- ทุกครั้งที่ผู้เล่นทำลายก้อนเมฆสำเร็จ ยานจะถูกปรับพิกัด Y ให้เพิ่มขึ้น (ลอยสูงขึ้นเพื่อหนีลาวา)
- หากปล่อยให้ก้อนเมฆตกลงไปชนลาวา ยานจะถูกปรับพิกัด Y ให้ลดลง
- เงื่อนไขจบเกม (Game Over) จะทำงานทันทีหากพิกัด Y ของยานมีค่าน้อยกว่าหรือเท่ากับพิกัดความสูงของลาวา

4. ระบบกราฟิกและแอนิเมชัน (Graphics & Animation)
- ออบเจกต์ในเกม (ยาน, เมฆ, ลาวา) ใช้ระบบ Canvas และ Widget ของ Kivy ในการวาดรูปภาพและลงสี
- มีการใช้ kivy.animation.Animation เพื่อทำระบบ Dynamic Background โดยสั่งให้รูปภาพพื้นหลังทำการเปลี่ยนค่าสี (Fade to black) และสลับภาพทุกๆ 15 วินาที โดยไม่รบกวนการทำงานของลูปเกมหลัก

5. ระบบเสียง (Audio Management)
- ใช้ SoundLoader ในการดึงไฟล์ .mp3 เข้ามาเก็บในหน่วยความจำ
- การเล่นเสียงจะถูกผูกติดกับเหตุการณ์ (Events) ต่างๆ เช่น เสียงคลิกปุ่ม, เสียงระเบิดเมื่อพิมพ์ถูก, เสียงเตือนเมื่อพิมพ์ผิด หรือการสั่งหยุดเพลงพื้นหลังเมื่อผู้เล่นแพ้หรือกดยอมแพ้
